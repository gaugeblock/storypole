# GB-36: Unified `.gaugeblock/` Configuration Directory Strategy and State Consolidation

> **Status:** Ready / Specified  
> **Target Scope:** `storypole-core`, `sawhorse-core`, `miter-storage`, `benchwork-core`, `benchwork-cli`, `workspace`  
> **Key Architecture Decisions:** D1 (Section-Isolated Reading), D2 (Unified Precedence & Legacy Fallback), D3 (Dual-Layer Git Ignores), D4 (Triple Migration Entrypoints: Benchwork, Meta-CLI, & Per-Tool), D5 (Safe Move with `--dry-run` & Backups)

---

## 1. Executive Summary & Vision

As the `gaugeblock` suite expanded across 9 distinct tools (`miter`, `storypole`, `sawhorse`, `chalkline`, `dado`, `batten`, `joiner`, `benchwork`, `rabbet`), tool-specific dotfiles and state directories began proliferating at the repository root:
- `.storypole/` (`config.toml`, `ledger.jsonl`, `index.sqlite`, `plans/`)
- `.miter/` (`config.toml`, `miter.redb`)
- `sawhorse.toml` (and `.sawhorse/`)
- `.dado/` (`patterns/`, `mixins/`)
- `.rabbet/spool/` (`outbox.jsonl`)
- `.benchwork/` (local telemetry, cache)

This scatter introduces root directory noise, fragmented gitignore configurations, redundant root configuration parsing, and poor developer ergonomics.

`GB-36` establishes a unified `.gaugeblock/` workspace directory standard across all 9 suite tools:
1. **Single Root Container (`.gaugeblock/`):** All tool-specific state, databases, outboxes, sandboxes, and configuration reside in a single, predictable directory.
2. **Master Hierarchical Configuration (`.gaugeblock/config.toml`):** A single unified configuration file containing dedicated tables for each tool (`[storypole]`, `[sawhorse]`, `[miter]`, `[rabbet]`, `[docs]`).
3. **Section-Isolated Reading:** Each tool parses only its own table from `.gaugeblock/config.toml` without depending on sibling tool crates or a monolithic schema crate.
4. **Transparent Backward Compatibility:** Tools check `.gaugeblock/` first, automatically falling back to legacy root dotfiles if `.gaugeblock/` has not yet been initialized.
5. **Universal 1-Click Migration:** Available via `benchwork migrate` (with a Benchwork UI banner), a dedicated `gaugeblock` meta-CLI, and per-tool migration commands.

## 2. Directory Layout & Git Lifecycle

```text
.gaugeblock/
├── .gitignore                      # Ephemeral ignore rules (sqlite, redb, spool, worktrees, datasets)
├── config.toml                     # Master unified configuration (replaces scattered toml configs)
├── docs.toml                       # 9-Document architecture mapping & policies (GB-18)
├── storypole/
│   ├── ledger.jsonl                # Git-tracked append-only task ledger & event stream
│   ├── index.sqlite                # Derived query index (ephemeral / gitignored)
│   └── plans/                      # Git-tracked rich Markdown execution plans
├── miter/
│   └── miter.redb                  # Symbol & AST graph database (ephemeral / gitignored)
├── dado/
│   ├── patterns/                   # Local pattern templates & overrides (git-tracked)
│   └── mixins/                     # Custom mixin definitions (git-tracked)
├── spool/
│   └── outbox.jsonl                # Joiner telemetry outbox (ephemeral / gitignored)
├── worktrees/                      # Miter / Joiner sandbox worktrees (ephemeral / gitignored)
└── datasets/                       # Local parquets, training runs, cache shards (ephemeral / gitignored)
```

### Git Tracking & Dual-Layer Ignores (Decision D3)
An auto-scaffolded `.gaugeblock/.gitignore` marks ephemeral and volatile artifacts while committing essential project memory:
```gitignore
# Ephemeral SQLite indexes & locks
storypole/index.sqlite*
# AST redb storage
miter/*.redb
# Outbox spool telemetry
spool/
# Sandbox worktrees and test environments
worktrees/
# Cache shards and parquets
datasets/
```

Workspace root `.gitignore` will also include:
```gitignore
.gaugeblock/storypole/index.sqlite*
.gaugeblock/miter/*.redb
.gaugeblock/spool/
.gaugeblock/worktrees/
.gaugeblock/datasets/
```

## 3. Master Unified Configuration Schema (`.gaugeblock/config.toml`)

```toml
[gaugeblock]
version = "0.1.0"
workspace_name = "neurosymbolic-suite"
telemetry_opt_in = true

[storypole]
ticket_prefix = "GB"
claim_ttl_minutes = 60
auto_track_git_branches = true

[sawhorse]
[sawhorse.default_model]
provider = "deepseek"
model_name = "deepseek-coder"
base_url = "https://api.deepseek.com/v1"
api_key_env = "DEEPSEEK_API_KEY"

[sawhorse.roles.oracle]
provider = "anthropic"
model_name = "claude-3-5-sonnet"

[miter]
exclude = ["target/**", "node_modules/**"]

[rabbet]
hub_url = "https://hub.gaugeblock.dev"
sync_interval_mins = 60
```

### Section-Isolated Reading (Decision D1 & D2)
Each standalone tool deserializes its respective table from `.gaugeblock/config.toml`. For example:
- `storypole-core` deserializes `#[derive(Deserialize)] struct ConfigFile { storypole: Option<StorypoleConfig> }`
- `sawhorse-core` deserializes `#[derive(Deserialize)] struct ConfigFile { sawhorse: Option<SawhorseConfig> }`
- If `.gaugeblock/config.toml` exists and contains the section, it is used.
- If missing, it checks legacy paths (`.storypole/config.toml`, `sawhorse.toml`, etc.).

## 4. Migration Engine & Tooling Strategy (Decisions D4 & D5)

The migration logic is implemented as a reusable engine inside `benchwork-core::migration`:
- **Detection:** Scans for `.storypole/`, `.miter/`, `sawhorse.toml`, `.dado/`, `.rabbet/spool/`.
- **Atomic Move:** Moves existing directories into `.gaugeblock/` subdirectories (`.storypole` -> `.gaugeblock/storypole/`, etc.).
- **Config Consolidation:** Reads legacy TOML files and generates a merged `.gaugeblock/config.toml`.
- **Dual-Layer Gitignore:** Scaffolds `.gaugeblock/.gitignore` and updates root `.gitignore`.
- **Safety:** Supports `--dry-run` and creates `.bak` backups before overwriting any collision.

### Migration Entrypoints
1. `benchwork migrate [--dry-run] [--force]`
2. `benchwork` Web UI: Automatic banner in Panel 1 / Status bar: *"Legacy dotfiles detected (.storypole, sawhorse.toml). Click to migrate to .gaugeblock/"*.
3. `gaugeblock migrate [--dry-run]`: Standalone root meta-CLI binary.
4. Per-tool migration commands: `storypole migrate` and `sawhorse init --migrate`.
